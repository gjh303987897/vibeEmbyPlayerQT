# rclone OneDrive 大文件上传故障修复

## 问题概述

通过 rclone 转发的 OneDrive 在上传大文件时失败。典型表现为：

- 客户端上传超时或返回失败；
- 挂载缓存目录中留下 `.part` 临时文件；
- OneDrive 端先出现同名的 0 字节对象；
- rclone 进程仍保持 HTTPS 上传连接，等待单请求上传完成或超时。

小文件上传不受影响，目录权限、挂载状态和剩余云端空间均正常。

## 服务结构

服务器上同时运行两个 rclone 服务：

- `rclone-onedrive-mount.service`：将 `onedrive:` 挂载到 `/mnt/onedrive`；
- `rclone-webdav.service`：将 `onedrive:` 通过本机 WebDAV 端口转发给应用。

应用使用的测试目录为 `/mnt/onedrive/test-dev`。实际部署时应替换为目标环境对应的挂载点和目录。

## 根因

OneDrive 后端未显式配置大文件分块上传参数。未达到上传分块阈值时，rclone 会尝试使用单请求上传；在本场景中，约 1.4 GiB 文件的单请求上传无法稳定完成，导致上传请求长期占用连接并最终失败。

另外，WebDAV 服务使用 VFS 写缓存时，HTTP `PUT` 返回成功只代表文件已经写入本地缓存；文件仍会在后台异步写回 OneDrive，不能立即以远端目录中的 0 字节占位对象判断最终结果。

## 修复方案

在两个 systemd 服务的 rclone 参数中加入 OneDrive 分块上传配置：

```text
--onedrive-upload-cutoff 4M
--onedrive-chunk-size 10M
```

完整参数示例：

```text
rclone mount onedrive: /mnt/onedrive \
  --vfs-cache-mode full \
  --cache-dir /var/cache/rclone \
  --buffer-size 64M \
  --onedrive-upload-cutoff 4M \
  --onedrive-chunk-size 10M
```

```text
rclone serve webdav onedrive: \
  --vfs-cache-mode writes \
  --cache-dir /tmp/rclone \
  --buffer-size 64M \
  --onedrive-upload-cutoff 4M \
  --onedrive-chunk-size 10M
```

说明：OneDrive 的 chunk size 必须是 320 KiB 的倍数，并且不应超过官方建议上限。`10M` 满足该约束；`4M` 阈值确保测试中的大文件走分块上传。

修改 systemd unit 前应先备份原文件，然后执行：

```bash
systemd-analyze verify /etc/systemd/system/rclone-onedrive-mount.service
systemd-analyze verify /etc/systemd/system/rclone-webdav.service
systemctl daemon-reload
systemctl restart rclone-onedrive-mount.service rclone-webdav.service
```

### Reverse proxy upload limits

If the public WebDAV endpoint is exposed through nginx, rclone's multipart
settings alone are not sufficient. An HTTP `413 Request Entity Too Large`
response is generated by nginx before the request reaches rclone. Configure
the WebDAV `server` block to accept large request bodies and stream them to the
upstream service:

```nginx
client_max_body_size 0;
client_body_timeout 3600s;
send_timeout 3600s;

proxy_request_buffering off;
proxy_buffering off;
proxy_http_version 1.1;
proxy_connect_timeout 60s;
proxy_send_timeout 3600s;
proxy_read_timeout 3600s;
```

`client_max_body_size 0` disables nginx's request-body size check for this
server. `proxy_request_buffering off` prevents nginx from writing the entire
upload to its own request-body temporary storage before forwarding it. Keep
these directives scoped to the WebDAV server instead of applying them globally.

Back up the nginx configuration, validate it, and reload without interrupting
active rclone processes:

```bash
nginx -t
systemctl reload nginx
```

## 全新重新部署

以下步骤适用于新服务器、重新安装系统或丢失原有服务文件的情况。所有带有占位符的值都必须替换为部署环境的实际值；不要将密码、OAuth token 或证书私钥写入脚本、Git 或日志。

### 1. 安装依赖并创建目录

```bash
apt-get update
apt-get install -y ca-certificates curl fuse3 nginx
install -d -m 700 /root/.config/rclone
install -d -m 700 /var/cache/rclone /tmp/rclone
install -d -m 755 /mnt/onedrive
```

安装与当前系统架构匹配的 rclone 稳定版，并确认 `rclone version` 能够正常执行。不要直接使用不明来源的二进制文件。

### 2. 配置 OneDrive remote

```bash
rclone config
```

创建一个名为 `onedrive` 的 remote，类型选择 `onedrive`，按照 rclone 交互引导完成 OAuth 授权，并选择正确的 drive 类型。然后执行：

```bash
chmod 600 /root/.config/rclone/rclone.conf
rclone lsd onedrive:
rclone about onedrive:
```

`rclone.conf` 只能由 root 读取，不要在终端输出完整配置。首次授权应在可信环境完成，并通过密钥管理或保密配置系统部署。

### 3. 创建 rclone 挂载服务

创建 `/etc/systemd/system/rclone-onedrive-mount.service`：

```ini
[Unit]
Description=Rclone OneDrive Mount
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=root
ExecStartPre=/bin/mkdir -p /mnt/onedrive /var/cache/rclone
ExecStart=/usr/bin/rclone mount onedrive: /mnt/onedrive --allow-other --vfs-cache-mode full --cache-dir /var/cache/rclone --vfs-cache-max-size 5G --dir-cache-time 72h --poll-interval 15s --buffer-size 64M --onedrive-upload-cutoff 4M --onedrive-chunk-size 10M
ExecStop=/bin/fusermount -uz /mnt/onedrive
Restart=always
RestartSec=10
LimitNOFILE=65536

[Install]
WantedBy=multi-user.target
```

`--allow-other` 需要 FUSE 允许非挂载用户访问；如果只有 root 使用，可以去掉该选项以减少暴露面。

### 4. 创建 rclone WebDAV 服务

创建 `/etc/systemd/system/rclone-webdav.service`：

```ini
[Unit]
Description=Rclone OneDrive WebDAV
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=root
ExecStart=/usr/bin/rclone serve webdav onedrive: --addr 127.0.0.1:8100 --user <WEBDAV_USER> --pass <WEBDAV_PASSWORD> --vfs-cache-mode writes --cache-dir /tmp/rclone --buffer-size 64M --onedrive-upload-cutoff 4M --onedrive-chunk-size 10M --tpslimit 5 --transfers 2
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

`<WEBDAV_USER>` 与 `<WEBDAV_PASSWORD>` 只能从部署密钥或秘密管理器注入，不能提交到仓库。更安全的做法是使用 systemd `EnvironmentFile`，并将该文件设置为 `0600`；不要把密码放在公开的 unit 文件中。

### 5. 配置 nginx HTTPS 反向代理

为公网访问创建一个仅转发到 `127.0.0.1:8100` 的 server block。证书和私钥路径使用实际环境的安全路径：

```nginx
server {
    listen <HTTPS_PORT> ssl;
    server_name <WEBDAV_HOST>;

    ssl_certificate     /path/to/fullchain.pem;
    ssl_certificate_key /path/to/private-key.pem;

    client_max_body_size 0;
    client_body_timeout 3600s;
    send_timeout 3600s;
    proxy_request_buffering off;
    proxy_buffering off;
    proxy_http_version 1.1;
    proxy_connect_timeout 60s;
    proxy_send_timeout 3600s;
    proxy_read_timeout 3600s;

    location / {
        proxy_pass http://127.0.0.1:8100;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

不要把 `client_max_body_size 0` 隆放到全局 `http` 块，只应用于 WebDAV server。确保防火墙仅放行必要的 HTTPS 端口，并不对公网暴露 rclone 的 `127.0.0.1:8100`。

### 6. 启用服务并按顺序检查

```bash
systemd-analyze verify /etc/systemd/system/rclone-onedrive-mount.service
systemd-analyze verify /etc/systemd/system/rclone-webdav.service
systemctl daemon-reload
systemctl enable --now rclone-onedrive-mount.service rclone-webdav.service
nginx -t
systemctl enable --now nginx
systemctl reload nginx
```

建议先检查本机 WebDAV，再从外部 HTTPS 地址检查，避免把 DNS、证书或防火墙问题误判为 rclone 上传问题：

```bash
curl -I http://127.0.0.1:8100/
curl -k -I https://<WEBDAV_HOST>:<HTTPS_PORT>/
systemctl is-active rclone-onedrive-mount.service rclone-webdav.service nginx
findmnt -T /mnt/onedrive
```

### 7. 执行首次功能验证

1. 用小文件验证目录创建、列表和删除。
2. 用大于 nginx 默认限制的文件验证 HTTPS WebDAV `PUT`，确认不是 `413`。
3. 等待 rclone 后台写回完成，再用 `rclone lsjson` 比较远端大小。
4. 通过挂载点再次读取已上传文件，确认挂载和 WebDAV 使用的是同一个 remote。
5. 删除所有测试对象，并保留 nginx、rclone 和 systemd 日志中的错误摘要。

全新部署完成后，应保存 unit 文件、nginx 配置模板、rclone 版本和验证结果，但不得保存 `rclone.conf` 原文、密码、OAuth token、证书私钥或 WebDAV Basic Auth 密码。

## 验证方法

### 1. 检查服务和挂载

```bash
systemctl is-active rclone-onedrive-mount.service rclone-webdav.service
findmnt -T /mnt/onedrive
pgrep -af '[r]clone (mount|serve webdav)'
```

两个服务都应为 `active`，并且进程命令行中应出现 `onedrive-upload-cutoff` 和 `onedrive-chunk-size`。

### 2. 使用 rclone 直传验证分块

```bash
rclone copyto /path/to/test.mp4 onedrive:test-dev/test-chunk.mp4 \
  --onedrive-upload-cutoff 4M \
  --onedrive-chunk-size 10M \
  --retries 3 \
  --low-level-retries 10 \
  --timeout 10m \
  -vv
```

日志中应出现 `Starting multipart upload` 和连续的 `Uploading segment`，结束时应有完整大小校验成功信息。

### 3. 验证挂载点写入

将大文件写入 `/mnt/onedrive/test-dev` 后检查：

```bash
rclone lsjson onedrive:test-dev --files-only --no-modtime --no-mimetype
rclone size onedrive:test-dev --json
```

远端对象大小必须与本地文件完全一致。上传刚开始时可能短暂显示 0 字节，这是 OneDrive 分块上传会话的占位对象；应等待后台提交完成后再判定结果。

### 4. 验证 WebDAV 上传

使用应用实际访问的 HTTPS WebDAV `PUT` 路径上传大于 nginx 默认限制的测试文件。先确认 nginx 返回 `201 Created` 而不是 `413`，再等待 rclone 后台写回完成。随后用 `rclone lsjson` 或 WebDAV `PROPFIND` 对比文件大小。仅看到 HTTP `201 Created` 不代表云端对象已经最终提交。

## 清理与回滚

测试文件应使用独立文件名，验证完成后删除测试产生的远端对象，避免污染用户目录。

若需要回滚：

1. 停止对应 rclone 服务；
2. 恢复修改前的 systemd unit 备份；
3. 执行 `systemctl daemon-reload`；
4. 重新启动两个服务并确认挂载恢复。

不要删除仍被 rclone 进程打开的 VFS 缓存文件。服务重启后，rclone 可能会继续提交尚未完成的缓存文件；应先检查进程、文件句柄和日志。

## 排查要点

- 使用 `journalctl -u <service>` 查找 `context canceled`、`Failed to copy`、`broken pipe` 等错误；
- 如果客户端收到 HTTP `413`，检查 nginx 错误日志中的 `client intended to send too large body`；该请求尚未到达 rclone；
- 使用 `lsof` 查看缓存文件是否仍被 rclone 打开；
- 使用 `ss -tinp` 检查到云端 HTTPS 连接是否持续发送数据；
- 区分挂载服务和 WebDAV 服务的缓存目录，避免两个 rclone 实例共享同一个 VFS 缓存；
- 不要在日志、文档或提交内容中记录真实的远程地址、用户名、密码、Basic Auth 密码、OAuth token、Drive ID 或配置文件原文。

## 2026-08-26 后续排查：不再是 413

如果 nginx 日志中已经没有 `413 Request Entity Too Large`，但 WebDAV 上传仍然失败，需要先区分 HTTP 状态码：

- `401` 表示 WebDAV Basic Auth 未通过。当前实测表明，使用服务器端正确凭据进行 16 MiB 和 256 MiB PUT 均返回 `201`；因此若应用日志持续出现 `401`，应在客户端删除并重新保存 WebDAV 服务密码，确保服务地址、用户名和密码与服务器端配置一致，然后重新选择 M3U8S 的 WebDAV 输出服务。
- `502` 出现在 nginx 向本机 rclone 写入请求体时，常见原因是后端在收到未认证请求后关闭连接；不能仅凭 `502` 判定为 OneDrive 分片大小问题。

只有在确认客户端认证正确后仍出现 `502`，才进一步将 WebDAV rclone 实例的 `--transfers` 降为 `1`，保留 `--onedrive-chunk-size 10M`，重启服务并重新执行中等大小 PUT 回归测试。
