# 2026-07-20 进入含 .m3u8sp 的 WebDAV 目录报错

## 现象

进入包含 `.m3u8sp` 文件的 WebDAV 目录时：

1. 先弹出自定义错误对话框（元数据读取失败）；
2. 后续修复后弹出 Windows 系统级 "Debug Error! abort() has been called"（Debug CRT）。

两者都由 2026-07-13 的带宽/GPU 优化引入（预览不再走 `prepareStream` 全量路径）。

## 根因一：尺寸上限（自定义错误对话框）

新的容器预览路径 `EncryptedHlsPlaybackProxy::resolvePreviewFromContainerHead()`
在 `manifestFromIndex` 中硬性要求清单条目完整装进 16 KiB 元数据窗口：

```cpp
if (!manifestEntry || ... || manifestEntry->size > m3u8sMetadataProbeBytes) {
    done(std::unexpected("M3U8SP manifest entry exceeds the listing preview window"));
```

真实打包的清单几乎必然超过 16 KiB（`#EXTM3U` 后固定跟 4096 字符 identifier 标签 +
base64 source-name 标签 ≈ 10 KiB，随后每个分片一行），每个真实 `.m3u8sp` 都落入
该错误分支；旧路径无尺寸上限。次要隐患：16 KiB 窗口在任意字节截断，可能把本地
化（CJK）分片名的多字节 UTF-8 字符切成半个。

修复：超尺寸条目改为仅 Range 读取 16 KiB 头部窗口（两个元数据标签恒在分片列表
之前）；读回后截断到最后一个完整行消除半个多字节字符的歧义；整条目 SHA-256 仅
在完整读取时校验（摘要按定义覆盖完整条目），播放路径 `prepareStream` 仍逐字节
完整验证。

## 根因二：moved-from std::function（系统 abort 对话框）

`manifestFromIndex` 以 `done = std::move(done)` 捕获回调，而其后的探测（64 KiB
probe）lambda 在其之后构造并捕获同一个 `done`——此时它已被移动为空。任何容器
探测失败（典型：服务器不支持 Range、返回 200，`fetchRemoteRange` 报
"does not support byte ranges"）都会调用空的 `std::function`，抛出
`std::bad_function_call`，穿透 Qt 事件循环触发 `std::terminate → abort()`，即
Debug CRT 的 "abort() has been called" 系统对话框。

修复：`std::function` 本身可复制，各阶段改为按值捕获副本，不再移动。

## 测试

- `containerPreviewSurvivesOversizedManifestWithUtf8Head`：真实
  `EncryptedHlsTarContainer::build()` 打包 >16 KiB、且 16 KiB 窗口边界恰好切进
  CJK 多字节字符的清单，经真实 HTTP Range 服务走预览路径，断言解析出正确 identifier。
- `containerPreviewReportsErrorWithoutRangeSupport`：不支持 Range 的服务器驱动容器
  探测失败路径。已验证：恢复旧捕获方式时该测试必然抛出未捕获异常（复现崩溃），
  修复后正常返回错误。
- 全部 ctest 通过。
