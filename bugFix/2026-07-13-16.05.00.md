# BugFix：WebDAV 加载 m3u8s/m3u8sp 文件名与识别码时 GPU 与网络带宽占用过高

日期：2026-07-13

## 症状

打开包含 m3u8s / m3u8sp 文件的 WebDAV 目录时：

- 网络带宽瞬时打满，目录内加密包越多越严重；
- GPU 持续高占用，即使画面静止也不下降；
- 反复进出同一目录会重复产生同样的大流量。

## 根因（四个独立问题叠加）

1. **网络：识别码读取按整文件下载**
   - `EncryptedHlsPlaybackProxy::resolveIdentifierPreview()` 对 `.m3u8s`
     走 `fetchRemoteBytes(..., 4MiB)` 且**不带 Range 头**，只为取清单头部
     的 4096 字符识别码行，最多整拉 4 MiB/文件。
   - 对 `.m3u8sp` 直接调用 `prepareStream()`，其中 `fetchRemoteRange(0,
     16MiB)` 预读整个 CBOR 索引前缀，同样只为一个识别码。
2. **网络：目录级无并发上限、无缓存**
   - `AppViewModel::loadWebDavDirectory()` 对目录内每个加密项**立即**发起
     预览请求；N 个文件 = N 个并发大下载；没有任何缓存，重复进入同一目录
     重复全量拉取。
3. **GPU：每个 pending 行一个无限 RotationAnimator**
   - `ThumbnailLoadingIcon` 每个实例内含 `RotationAnimator`（900ms、
     Infinite）+ 8 个独立 Rectangle；每行元数据未就绪前都持有一个，列表
     几十行即数十个持续动画节点，渲染线程被钉在刷新率上。
4. **信号风暴：逐网络块 emit**
   - `fetchRemoteBytes/fetchRemoteRange`、`WebDavPlaybackProxy`、
     `TransferManager::updateProgress` 都在每个 readyRead/进度回调上
     `emit networkTrafficSample(...)`，大流量时每秒数百次信号进入 UI 层。

## 修复

### 1. 识别码改为小窗口 Range 探测（`.m3u8s` 16 KiB / `.m3u8sp` ≤128 KiB）

- `HlsManifestValidator` 新增 `parseMetadataHead()`：只解析清单头部窗口内
  的 `#M3U8S-IDENTIFIER:` / `#M3U8S-SOURCE-NAME:` 两个标签行；窗口在标识
  符行中间、源名行中间或止于标识符行（缺尾换行）等任何截断歧义场景返回
  错误，由调用方回退旧的整读路径，行为在异常服务器上保持等价。
- `resolvePreviewFromFullManifest()`：先发 `Range: bytes=0-16383`，头部
  窗口解析成功即返回（一次 16 KiB GET 代替最多 4 MiB）；服务器不支持
  Range 或窗口非法时回退历史整读路径。
- `resolvePreviewFromContainerHead()`：`.m3u8sp` 不再走 `prepareStream`
  的 16 MiB 索引预读，改为 64 KiB 探测窗口 →（索引超出窗口时）按 TAR 头
  声明的精确大小一次加宽 → 一次目标 Range 读取清单条目（几 KiB，带
  SHA-256 校验）。`EncryptedHlsTarContainer` 新增
  `indexSizeFromPrefix()`，`readIndexPrefix()` 支持 `containerLength < 0`
  跳过总长交叉校验（探测窗口尚无可信总长）。
- 头部窗口拿不到 root digest，故源文件名改由本地 TSSL 库按 identifier
  反查：`TsslStore::sourceFileNameByIdentifier()` 新接口 + proxy 内惰性
  索引（miss 时强制重扫一次，覆盖会话期间新导入的包）。

### 2. 预览队列限并发 + 指纹缓存

- `resolveIdentifierPreview()` 增加 `revision` 参数（调用方用
  `size|lastModified` 指纹）。请求入队，最多 4 个并发；结果按
  `url + revision` 缓存（成功 5 分钟、失败 30 秒，容量 4096 防膨胀）。
  远程文件变化 → 指纹变化 → 自动重新解析。旧四参调用以空 revision 兼容
  （禁用缓存），既有测试与调用点不破坏。

### 3. Spinner 由连续动画改 8 帧步进

- `ThumbnailLoadingIcon` 的 `RotationAnimator` 替换为 `Timer`（900/8ms）
  驱动 `rotation = step * 45`，并只在 `visible && running` 时运行。视觉
  效果等价（该 spinner 本就是 45° 离散步进观感），但场景图每 112ms 才有
  一次属性变更，动画间隙渲染循环可休眠，几十行 pending 不再钉死 GPU。

### 4. 流量信号聚合（新公共模块）

- 新增 `src/utils/NetworkTrafficCoalescer.{h,cpp}`：按 serviceId 分桶、
  200ms 合并窗口、`flush()` 立即冲刷。
- `WebDavPlaybackProxy`、`TransferManager`、`EncryptedHlsPlaybackProxy`
  的热路径逐块 `emit` 改为 `m_traffic.record(...)`，各自的
  `networkTrafficSample` 对外签名不变，`AppViewModel` 消费端零改动。
- 模块文档见 `VIBEDOCS/NetworkTrafficCoalescer.md`。

## 效果对照（目录含 N 个加密包，全部首次加载）

| 路径 | 修复前 | 修复后 |
| --- | --- | --- |
| `.m3u8s` 单文件 | ≤4 MiB 整读 | 16 KiB Range 一次 |
| `.m3u8sp` 单文件 | 16 MiB + 清单 4 MiB | 64–128 KiB + 清单条目几 KiB |
| 并发 | N（无上限） | ≤4 |
| 重复进目录 | 全量重来 | 指纹命中缓存，零流量 |
| spinner | 每行 60fps 连续动画 | 每行 ~9fps 步进，空闲可休眠 |
| 流量信号 | 每块 1 次（数百/秒） | 每 200ms 1 次 |

## 验证

- 全量构建（clang-cl/Ninja）零错误。
- `ctest` 18/18 通过，含新增：
  - `previewUsesSingleRangedProbeAndCachesResult`：Ranged 伪造服务器上
    预览只发生 1 次请求；同指纹二次预览 0 请求。
  - `previewFallsBackToFullReadWithoutRangeSupport`：非 Range 服务器回退
    整读路径仍解析成功。
  - `metadataHeadParsesWindowsWithoutSourceNameAndRejectsCuts`：头部窗口
    解析 / 各类截断必须回退。
- 应用冒烟启动正常（窗口存在、无 QML 错误输出）。

## 影响面

- 仅列表预览路径改变网络行为；播放路径（`prepareStream` /
  `serveSegment` / TSSL 校验）完全未动，安全边界（清单校验、条目
  SHA-256、identifier/TSSL 一致性）保持不变。
- 对不支持 Range 的服务器行为与修复前一致（回退路径）。
